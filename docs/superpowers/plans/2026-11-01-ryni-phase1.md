# Rýni Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A self-hosted, privacy-preserving web analytics tracker (Ackee-like, no cookies, DNT-aware) with two same-script integration variants (direct + same-origin proxy), a SolidJS dashboard, per-site user permissions, OIDC SSO, and backup — running under `docker compose up`.

**Architecture:** PocketBase backend exposes an anonymous ingest route and authenticated stats routes via `pb_hooks`; collections are defined in `pb_migrations`; the SolidJS frontend consumes the PocketBase API and serves the standalone tracker script; Docker Compose runs both containers. Aggregations are server-side (never pull all records to the browser).

**Tech Stack:** PocketBase ≥0.40 (JS hooks + migrations), SolidJS + Vite + TypeScript + Tailwind + `@solidjs/router` + `@ark-ui/solid` + `lucide-solid` + `pocketbase` client, vitest (backend integration + frontend unit), Docker Compose, GitHub Actions (thin CI).

**Spec:** `docs/superpowers/specs/2026-11-01-ryni-design.md`

## Global Constraints

- PocketBase **v0.40.4** (pin in `pocketbase/Dockerfile`), Node **24** (`node:24-alpine` build image), nginx-unprivileged **1.27**.
- License **AGPL-3.0-or-later**; `LICENSE` already committed; add an SPDX header comment to every new source file.
- **No cookies, no raw IP** anywhere in Rýni code. Visitor identity = random `localStorage` id only.
- Ingest endpoint and script filename must be innocuous/configurable — never literally `tracker.js`, never `/api/track`.
- Ingest is anonymous and hot: answer in single-digit ms; no auth token; drop unknown sites with 404.
- Frontend is TypeScript throughout; tracker is the only standalone browser script (built to IIFE, no framework).
- All PocketBase custom routes follow the STJÓRNA split: thin `pb_hooks/*.pb.js` router file + handler in `pb_hooks/lib/*.js` loaded via `require(`${__hooks}/lib/x.js`)`.

## Review Focus

The five inputs/failure modes most likely to bite a user, each pinned by a test in the owning task:

1. **Variant A CORS**: a direct (cross-origin) tracking request from a non-allowlisted origin must be rejected, and from an allowlisted origin must succeed with the right `Access-Control-Allow-Origin`. → Task 3.
2. **Unknown/forged site**: a request with an unknown `endpoint_slug` or `tracking_id` must 404 and create no record. → Task 3.
3. **DNT honored**: when `navigator.doNotTrack === "1"`, the tracker sends nothing. → Task 5.
4. **Session math**: crafted records must produce correct uniques/bounce/duration — 30-min gap splits sessions, a single-view session is a bounce, null-duration final views are excluded from average (never counted as 0). → Task 4.
5. **Permission leak**: a non-member must get 403 on a site's stats, a `viewer` must not create/update/delete a site or its shares. → Task 2 + Task 4.

### Task 3: Anonymous ingest route

**Files:**
- Create: `pocketbase/pb_hooks/ingest.pb.js`
- Create: `pocketbase/pb_hooks/lib/ingest.js`
- Create: `pocketbase/tests/ingest.test.ts`

**Interfaces:**
- Produces: `POST /t/{slug}` — anonymous. Request JSON body:
  `{ visitor: string, type?: "view"|"end"|"heartbeat", page?: string, referrer?: string, browser?: string, os?: string, device?: string, screen?: string, duration?: number }`
  - `type:"view"` → create a `records` row (duration = null), and upsert `heartbeats` for `(site, visitor)` with `last_seen=now`. If `duration` present, apply it to the most recent `records` row for `(site, visitor)` with null duration.
  - `type:"end"` → set `duration` on the most recent null-duration `records` row for `(site, visitor)`; remove the heartbeat.
  - `type:"heartbeat"` → upsert `heartbeats` only.
  - `is_new_visitor` = true when `(site, visitor_id)` has never been seen before.
- Produces: resolves site by `slug` (path); if `slug` unknown → 404 empty. For a request carrying an `Origin` header, if that origin is not in the site's `allowed_origins` → 403 and no record; otherwise respond with `Access-Control-Allow-Origin: <origin>` (Variant A). Variant B (no `Origin`) is allowed (trusted self-host).
- Consumes: collections from Task 2.

- [ ] **Step 1: Write failing tests**

`ingest.test.ts`:
- `POST /t/<slug>` with valid body → 200, one `records` row created, `is_new_visitor` true; second `view` from same visitor → `is_new_visitor` false.
- Unknown slug → 404, zero records.
- Disallowed `Origin` → 403, zero records; allowed `Origin` → 200 + `Access-Control-Allow-Origin` echo.
- `type:"end"` with `duration: 12` sets duration on the prior null-duration row.

- [ ] **Step 3: Implement `ingest.pb.js` + `lib/ingest.js`**

`ingest.pb.js`: `routerAdd("POST", "/t/{slug}", (e) => { require(`${__hooks}/lib/ingest.js`).handler(e); })`. `lib/ingest.js` `handler(e)`: resolve `e.request.pathValue("slug")`, `$app.findFirstRecordByFilter("sites", "endpoint_slug={:s}", ...)`, enforce origin, parse body, branch on `type`, write records via `$app.save`, return `e.json(200, {ok:true})`.
